# Методика разработки pve_center

Дополнение к [AUDIT_PROCESS.md](AUDIT_PROCESS.md): как ведётся разработка,
чтобы следующий аудит находил как можно меньше. Принцип тот же — процесс
подгоняется под реальность соло-проекта, а не наоборот.

## Среда

- Локальная среда — `.venv` (Python 3.12). Запуск — **только**
  `.venv/bin/python`, не `uv run` (`uv` — только для lock-файла).
- CI (`.github/workflows/ci.yml`) гоняет **только ruff** (3.10/3.11/3.12).
  Тесты — ответственность разработчика локально, перед каждым коммитом.
- Репо — прямой push в `main`; PR-правила обходятся намеренно (соло).

```bash
.venv/bin/python -m pytest tests/ -q          # все тесты (~730, <2 мин)
.venv/bin/ruff check pve_center/ tests/       # линт (gate до и после правок)
uv lock                                       # только при изменении зависимостей
```

## Рабочий цикл

1. **Задача** — берётся из [FEATURES_BACKLOG.md](../FEATURES_BACKLOG.md)
   (батчи `B<n>` / идеи `F<n>`) или [ROADMAP.md](../ROADMAP.md); новая фича
   сначала записывается туда с номером, потом код. Баги — GitHub Issues,
   журнал работ — [bugs.md](bugs.md).
2. **Большая фича** — режется на этапы (`B17 stage 1/2`), каждый этап —
   самостоятельные коммит(ы) с рабочим UI.
3. **Реализация** — по правилам кодирования ниже (зеркало чеклиста аудита).
4. **Гейты** (зелёные до коммита, не «потом»):
   ruff + pytest; при касании `tr()` — паритет i18n; при релизе — версии.
5. **Коммит** (стиль ниже). Релизы и аудиты — с тегами.

## Коммиты

- Формат: `тип: краткое описание` строчными. Типы как в истории:
  `feat`, `fix`, `perf`, `refactor`, `test`, `docs`, `release`, `audit`.
- Один коммит = одна логическая единица; фикс бага из аудита — вместе с
  регресс-тестом и отчётом.
- Теги: `vX.Y.Z` — релизы (запускает `release.yml`: deb/rpm/zip/installer),
  `audit/<дата>` — точки аудита.

## Версии и релизы

- Нумерация (см. FEATURES_BACKLOG): багфикс `2.9.X`, фича `2.X.0`, мажор `X.0.0`.
- Релиз = одно и то же число в `pyproject.toml` **и** `pve_center/__init__.py`
  (не бампать только одно), запись в [CHANGELOG.md](../CHANGELOG.md) сверху
  (на английском, секции **New features** / **Bug fixes** / **Performance** /
  **Internal**, в Internal — счётчик тестов `N tests (+M)`), коммит
  `release: vX.Y.Z — ...`, тег, push тега.

## Правила кодирования

Короткий список для *написания* кода (что проверяет аудит — в
[AUDIT_PROCESS.md](AUDIT_PROCESS.md), чеклисты должны совпадать):

**Воркеры / потоки** (`backend/`, `ui/api/`):
- новый запрос к PVE/PBS — через `create_provider(cfg)` (или фабрику
  `build_requests_session(cfg)` для raw-requests), а не голый `requests`/proxmoxer;
- provider/session закрывается в `finally`;
- все `signals.*.emit()` — в `try/except RuntimeError` (виджет мог умереть);
- из фонового потока — никаких обращений к Qt-объектам;
- таймауты соразмерны операции (клон ≠ снапшот).

**UI**:
- новый вид объекта в дереве = согласовать ключи дерево ↔ поиск ↔ detail
  (3 места, см. чеклист аудита) до коммита;
- порядок табов detail — только через `TabIndex`, не сырые индексы;
- окна с тяжёлыми детьми (`QWebEngineView`) — `WA_DeleteOnClose`.

**Конфиг / БД**: sqlite — под `_DB_LOCK`; новые поля экспорта/импорта —
сразу в `_ALLOWED_IMPORT_FIELDS` (+ регресс roundtrip).

**i18n**: каждый новый `tr("...")` — во все 5 локалей сразу (не «потом»),
изменение словарей = bump `_I18N_VERSION`. Проверка паритета — скрипт из
аудит-методики.

**Производительность** (паттерн v2.11.x, не деградировать):
- тяжёлые импорты (`requests`, `pyqtgraph`) — локальные/отложенные, не top-level;
- построение UI — чанками, не всё сразу в `__init__`.

**Зависимости**: pin с обоснованием в комментарии (`websockets>=14.0` —
пример); после правки — `uv lock` в том же коммите.

**Стиль**: без комментариев «что» (код сам), только «почему»/ловушки;
LSP-шум Qt-стабов (`Qt.WA_*`, `QIcon | None`, mock-атрибуты) — игнорируется,
как и в аудите.

## Тесты

- Зоны зеркалят код: `tests/backend/`, `tests/config/`, `tests/provider/`,
  `tests/pbs/`, `tests/ui/`. Qt-тесты — `pytest-qt` + offscreen (ставит
  conftest).
- **Регресс-тест обязателен** на каждый багфикс — имя теста описывает
  сценарий (`test_stop_before_loop_assigned_no_leak`).
- Тесты не трогают реальный профиль пользователя: autouse-фикстура
  `_isolate_xdg` в `tests/conftest.py` уводит `XDG_*_HOME` в tmp — не
  обходить её через жёсткие пути.
- Внешние сервисы не дёргаются: фейк-провайдеры/monkeypatch
  (`create_provider`, `FetchWorker`), сокетные тесты — только localhost.

## Связь с аудитом

- Каждый нетривиальный коммит — кандидат в дельту следующего аудита
  (`audit/<дата>..HEAD`); писать код так, чтобы diff читался.
- 🟡-наблюдения из отчётов — не забыты: учитываются при следующем касании
  файла («кандидат на helper при следующем касании» — реальный механизм).
- Инструментальный анализ (bandit, pip-audit) — раз в релиз, отдельной
  задачей (см. аудит-методику).
