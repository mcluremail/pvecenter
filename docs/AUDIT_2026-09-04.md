## 🔴 Найдено и исправлено (в этом же коммите)

### E1. Глобальный поиск не мог прыгнуть к локальному хранилищу ноды кластера
`domain/search.py`: ключ storage-результата строился по условию
`if storage.cluster:` → локальное хранилище ноды кластера получало
cluster-scope ключ `("storage", name, "cluster", cl)`. После B20 в дереве
такого элемента нет (локальные хранилища висят под хостом с ключом
`("storage", name, "host", host)`), переход молча не срабатывал
(например, поиск «local» в кластере). Исправлено: cluster-scope ключ только
для `storage.shared` — ключи поиска теперь зеркалят дерево. Регресс-тесты:
`test_storage_shared_in_cluster`, `test_storage_local_on_cluster_node`.

## 🟡 Наблюдения (не исправляем, зафиксировано)

1. `_edit_note_dialog`/`save_tree_note` — нормализуют `strip()` при записи;
   заметки с пробелами по краям не сохраняются — осознанно.
2. `conn.close()` в config.py стоит внутри `try` — при исключении соединение
   утекает. Паттерн старый, для десктопа некритично; кандидат на глобальную
   чистку (contextlib.closing) при следующем касании config.py.
3. `reveal_key` знает только про storage-ключи; при добавлении новых видов
   (например, «Pools») переключение режима надо расширять там же.
4. `metrics.py`/backend используют `if provider:` как None-guard — корректно
   (у `ProxmoxProvider` нет `__bool__`), но читается как truthiness-проверка.
