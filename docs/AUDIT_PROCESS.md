# Методика аудита кода pve_center

Принцип: приложение большое — каждый аудит проходит **не весь код**, а только
дельту с прошлой точки аудита плюс точечные зоны риска. Полный проход —
редкое событие (мажор или массовый багрепорт), а не рутина.

История аудитов: [AUDIT_2026-06-20.md](AUDIT_2026-06-20.md) (полный, 37
файлов), audit batch 1–7 (коммиты `8a07bc7`…`8fc6c82`, дельта разработки
2.10), [AUDIT_2026-09-04.md](AUDIT_2026-09-04.md) (первый по этой методике).

## Точки аудита

- **Точка аудита** = git-тег `audit/<дата>` на коммите аудита
  (например `audit/2026-09-04`).
- **Scope очередного аудита**:
  ```bash
  git log --oneline audit/<prev>..HEAD        # список коммитов (docs — просмотреть мельком)
  git diff audit/<prev>..HEAD --stat          # объём
  git diff audit/<prev>..HEAD -- '*.py'       # собственно код
  ```

## Процедура

1. **Scope**: перечислить коммиты дельты, выкинуть чисто-документационные.
2. **Diff-чтение**: каждый файл дельты — прочитать diff целиком (с контекстом,
   не только `+/-` строки). Механические правки (переименования, миграции
   шаблонов) — проверить на *единообразие* (`rg` по старым именам), а не
   читать каждую строку.
3. **Чеклист** (по категориям изменений — см. ниже).
4. **Исправление**: подтверждённые баги чинятся в коммите аудита + обязательно
   регресс-тест. Спорное — в раздел 🟡 наблюдений, не чинить молча.
5. **Отчёт** `docs/AUDIT_<дата>.md`: scope таблицей, 🔴 исправлено,
   ✅ проверено-чисто, 🟡 наблюдения.
6. **Тег** `audit/<дата>` на коммит аудита, push, тег push.

## Чеклист по категориям изменений

**Воркеры / потоки** (`backend.py`, `ui/api/`):
- provider/session закрыт в `finally` (в т.ч. при `return` внутри `try`);
- `signals.*.emit()` обёрнуты в `try/except RuntimeError` (виджет мог умереть);
- нет обращений к Qt-объектам из фонового потока;
- таймауты ожидания задач соответствуют операции (клонирование ≠ снапшот).

**Ключи объектов** (дерево ↔ поиск ↔ detail_panel):
- формат ключей совпадает во всех трёх местах (`ITEM_KEY_ROLE` / `VM_KEY_ROLE`
  в дереве, `key` в `domain/search.py`, `data`-dict в `show_details`);
- новый вид объекта = проверить все три + `reveal_key`/`find_item_by_key`;
- B20: ключ может быть 2-, 4-элементным — контекст-меню/клики/удаление должны
  переживать обе длины.

**Конфиг / БД** (`config.py`):
- обращения к sqlite под `_DB_LOCK`; соединение закрывается;
- новые таблицы добавлены и в `_init_db`, и покрыты тестом;
- ошибки логируются, не глотаются молча.

**i18n**:
- каждый новый `tr("...")`-ключ есть во всех 5 локалях (паритет длин JSON);
- при изменении существующих — bump `_I18N_VERSION`;
- проверка: `python -c` паритет ключей по локалям (см. отчёт 2026-09-04).

**Мёртвый код**:
- после удаления сигнала/метода — `rg` по имени во всём репо (включая тесты);
- после удаления ветки UI — проверить, что `mainwindow`-connect тоже удалён.

**Тесты**:
- на каждый 🔴 — регресс-тест;
- тесты не пишут в реальный пользовательский config.sqlite (изоляция
  ui_state/notes через monkeypatch — пример: `_isolated_tree_state` в
  `tests/ui/test_tree_panel.py`);
- `.venv/bin/ruff check pve_center/ tests/ && .venv/bin/pytest -q` зелёные.

**Безопасность**:
- секреты (токены, пароли) не попадают в логи, json-кэш, исключения;
- `subprocess`/`requests` — аргументы списком, `allow_redirects=False`
  для raw-вызовов с Authorization;
- `verify=...` для SSL — всегда из конфига узла, не константа.

## Что НЕ входит в рутинный аудит

- Полный проход по файлам вне дельты — только на мажор (X.0.0) или по
  мотивам багрепортов.
- Инструментальный статический анализ всего проекта (bandit, pip-audit) —
  раз в релиз, отдельной задачей.
- LSP-диагностика Qt-стабов (`Qt.UserRole`, `QIcon | None` и т.п.) — шум,
  игнорируется (проверять только «possibly unbound»/unused, и то с чтением кода).

## Механические проверки (можно автоматизировать позже)

```bash
# паритет i18n
.venv/bin/python - <<'EOF'
import json, pathlib
ls = ["ru","es","fr","ar","zh"]
sets = {l: set(json.loads(pathlib.Path(f"pve_center/ui/i18n/{l}.json").read_text())) for l in ls}
ref = sets["ru"]
for l in ls: assert sets[l] == ref, f"{l}: {ref ^ sets[l]}"
print("i18n parity ok:", len(ref))
EOF
# остатки старого API после миграций
rg -n "ProxmoxSession|_poll_task" pve_center/ --glob '!pve_center/provider/**'
```
